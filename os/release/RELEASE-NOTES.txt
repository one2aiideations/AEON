# @PRODUCT_NAME@ - Release Notes
Version @VERSION@ - @DATE@

Author: Chandra Mouli Krishna Moorthy - cmklive@gmail.com

## What this release is

A bootable, Linux-based image of @PRODUCT_NAME@ for 64-bit PCs. It starts from a USB stick (BIOS and UEFI), shows the MOULI logo, probes the hardware, lets you pick a language model from a disk or USB stick, and chats with it locally and offline, in a graphical desktop window (or on the text console if no screen or input device can be used). Optionally it connects over Ethernet or Wi-Fi, and can chat with a hosted model after you agree that messages leave the computer.

ISO SHA-256: @ISO_SHA256@

## What is in the image

- Linux kernel 6.18 with drivers for common wired and Wi-Fi adapters and the firmware for common Intel, Realtek, MediaTek and Atheros Wi-Fi chips.
- moulid, the MOULI start-up program written in Rust: console, networking, hardware plan, model menu, chat, saving settings.
- llama.cpp as the local inference engine (CPU).
- A small set of system tools (BusyBox, wpa_supplicant, iw).

Licences of all parts are listed in 05-Licensing/LICENSE.txt.

## Features

- Start-up logo with the product and author details: on the screen it is a large block-letter logo in Material Design colours (plain text on a serial console, or with mouli.plain=1).
- Hardware report and automatic choice of threads and context size.
- Model menu listing every .gguf file on any disk or USB stick, with a memory check. Models you copy onto a disk or stick yourself keep working as before.
- Model download: press d in the model menu to fetch a model over the network (Ethernet or Wi-Fi) onto the MOULI-DATA partition. The list is built in (Qwen2.5 1.5B and 3B, Llama 3.2 1B and 3B); each file is checked against its size and SHA-256 before it is kept, interrupted downloads resume, and the server and licence are shown before anything is downloaded. Needs a MOULI-DATA partition, a network connection and free space.
- Graphical desktop drawn on the screen's framebuffer: menu bar, icons and windows, with the chat in a window. Keyboard (US layout), a USB or PS/2 mouse, touchpads (Apple, Elan, Synaptics and multitouch pads: move, tap to click, press to click, two-finger scroll) and Bluetooth mice and trackpads. Mice and touchpads plugged in or connected after the desktop started are picked up, and the chat window lists the input devices found. Keys: Enter sends, Ctrl+N starts a new chat, Ctrl+W closes a window, Ctrl+Q shuts down. F1 Chat, F2 Models, F3 Approvals, F4 Audit, F5 Security, F6 Review, F9 Code, F11 Storage, F12 Preview, Ctrl+B Browser. Add mouli.text=1 to the kernel command line for the text chat only.
- Bluetooth: press b in the model menu to scan, pair, trust and connect a mouse or trackpad that pairs without a code (BlueZ). With a MOULI-DATA partition the pairing is kept in plain text on it and reconnects at the next start.
- Code window: a code editor with a file list, selection and clipboard, undo, find, go to line, bracket matching and colouring for HTML, CSS, JavaScript, JSON, Python and Shell. Edits go to review before they are applied. With a MOULI-DATA partition it opens the folder projects/ on it; without one nothing is saved, and the desktop says so.
- Preview window (F12): renders HTML, Markdown and text with MOULI's own web engine (HTML, CSS with flexbox, grid and floats, PNG, JPEG and GIF pictures, and a JavaScript interpreter for page scripts). No other browser engine is used.
- Browser window (Ctrl+B): address bar, history, links, forms that use GET, style sheets, scripts and pictures. A page on the internet cannot make the browser load anything from this computer or the local network. A reading view and a summary by the assistant are available; page text reaches the model marked as data.
- Storage window (F11): what is on the data disk, free space, and removing a model.
- Accounts and passphrase sign-in (new in 1.6): with a MOULI-DATA partition, the owner types /passwd to set a passphrase; from then on the desktop starts locked and only /signin <name> works. The passphrase is typed in a hidden line (shown as stars, never kept in the chat, the audit log or any file); the file on the data disk keeps only a salted, stretched check of it, readable by its owner only. A person's role comes from their account, not from what they type. The owner adds accounts with /adduser <name> <role>, changes roles with /setrole, removes accounts with /deluser, resets passphrases with /resetpass and lists accounts with /users; the last owner cannot be removed or demoted. Five wrong passphrases lock a name out until someone who can approve types /unlock <name>. If every owner forgets their passphrase, the file users.txt on the data disk has to be removed by hand.
- Security window (new in 1.6): findings come from rules over the audit log and are scored together; repeated refusals lock a person out; bursts of refusals are flagged; a finding can be marked as seen (written to the audit log, kept across restarts); evidence for a finding can be saved to a file (key e); an audit checkpoint (HMAC-SHA-256 with a key kept beside the log) reports a log that was cut, swapped or rewritten.
- The audit chain, held approvals and each person's conversation are kept on the MOULI-DATA partition and restored at the next start; a damaged file is refused and never overwritten.
- More windows (new in 1.6): Settings (Ctrl+O: contrast and text size), Wi-Fi (Ctrl+E: scan, choose, hidden password, join), audit search (/ in the Audit window), chat commands /help, /apps, /files and /save, answers that stream in as they are produced and stop with Ctrl+C, a screenshot with Ctrl+P (PNG on the data disk), idle screen blanking, and /contrast and /textsize.
- Removing private details before text leaves the computer now also catches JSON passwords and keys, Authorization headers, passwords in addresses and more key formats.
- The desktop puts the console back if it crashes and shuts down cleanly on the terminate signal.
- Faster local inference: matrix products use several threads and cores (about 2.8 tokens per second when generating with the 1B model on the author's build machine, up from 0.29; other computers will differ).
- Text chat with commands /models, /clear and /quit when the desktop is not used.
- Optional MOULI-DATA partition that keeps the last model used and the chat logs.
- Wired network by DHCP, clock set from the network, Wi-Fi setup screen, hosted-model chat with key entry and washing of personal data (GDPR and DPDP profiles) such as emails, card numbers and passwords. A saved API key is encrypted with a passphrase.

## How it was tested

- Automated tests of the Rust code (unit and integration).
- The image is built and started in QEMU under BIOS and UEFI with a very small test model. The test checks the start-up output, a chat reply, saving to a MOULI-DATA disk and reading it back, wired networking, and Wi-Fi against virtual radios.
- The screen is checked with a virtual display under BIOS and UEFI.
- The desktop was tested in QEMU with a virtual screen, keyboard and mouse: it drew, took typed text, answered through the model and followed mouse movement.
- The text chat (version 1.0) was reported working by the author on one 2017 MacBook Air with a Qwen model. The desktop has NOT yet been tried on a real PC.
- Version 1.6: the image was rebuilt and booted in QEMU (BIOS) to the model menu, with a screenshot check that the screen shows output. The new windows, the account commands and the locked start were tested by automated tests of the controller and the screens, not by looking at them on a real screen or typing on a real keyboard.
- It has NOT been tested with real Wi-Fi radios (the Wi-Fi window was tested with a fake scanner only), or for speed and memory with a full-size model.

## Known limitations

- In the desktop the Chat, Code, Approvals, Audit and Security windows are connected to the governed workspace (policy, approvals, audit chain). Sheet, Studio, Player and CRM are not part of this image. There is no video player or sound.
- The browser and preview engine are new and have only been tested against test pages, not on real PCs. Many real web sites will not display correctly: POST forms, cookies, downloads, tabs, WebP and SVG pictures, JavaScript generators and Symbol are not supported, and Date uses UTC only.
- Choosing a model is still done in the text menu before the desktop starts. There is no Users window: accounts are managed with chat commands.
- Downloading was tested over real HTTPS from inside the virtual machine (a 807 MB model, hash checked) but not yet on a real PC or over Wi-Fi. Only Hugging Face servers are allowed; there is no custom address option yet. Check each model's licence (the Qwen 3B model is non-commercial).
- Touchpads and Bluetooth are NEW and have not been tried on real hardware: only generated finger events and a virtual setup were tested. The pointer scale on a touchpad is learned, so the first sweep across the pad may overshoot. Bluetooth needs an adapter whose firmware is built in or included (CSR and Intel adapters work; many Broadcom and some Realtek ones need a firmware file that is not in this image). Keyboards that ask you to type a code, headsets and audio are not supported. The keyboard layout is US.
- CPU inference only. No GPU acceleration. The CPU must support AVX2 (2013 or newer).
- Secure Boot must be off. There is no installer: it runs from the stick and keeps nothing unless a MOULI-DATA partition is present.
- US keyboard layout only.
- Wi-Fi: no WPA3-only, enterprise or hidden networks; Broadcom chips are not supported. Networks you join in the Wi-Fi window are remembered on the data disk; this was tested with fakes only.
- The terminate signal is now handled, but not yet tried against a real shutdown on a framebuffer. Orphaned processes are still not cleaned up.
- Sign-in locks the desktop's controls, but a desktop window that was already open can still show its contents, and someone who can read the data disk can try passphrases offline against the stored checks. Chat logs and Bluetooth pairings on the MOULI-DATA partition are stored as plain text. A saved API key is stored encrypted, but its strength depends on the passphrase you choose.

## Upgrading

There is nothing to upgrade in place. Write the new ISO to the stick as described in the Installation Guide. Files on a separate MOULI-DATA partition are kept as long as that partition is not overwritten.

## Verifying this release

Use the SHA256SUMS file in 03-Verification as described in the Installation Guide.
